# Stories page design

Date: 2026-09-20
Status: approved in conversation, awaiting implementation

## Goal

Replace the placeholder signed-in home at `/home` (the "Stories" nav item) with
a page that lists the user's games as story cards in three sections, lets them
create a new story, and establishes the app's data access convention: every
read and write is a server action that verifies the session and the user row
before touching the database.

## Scope

In scope:

- Schema: `games.summary`, `games.is_looking_for_players`, new `game_favorites`
  table, Drizzle mirrors for `games`, `systems`, `game_players`,
  `game_favorites`.
- The `/home` page with header, three sections, load-more, story cards with a
  summary popover.
- The `/home/new` page with a create form.
- A `/home/[id]` stub so card clicks land somewhere.
- `requireUser()` guard and the `actions.ts` module.
- Summaries added to the games seed.
- Tests as listed below.

Out of scope (later work): favoriting from the UI, editing a story, image
upload to Vercel Blob, the story detail page beyond a stub, joining a game as a
player.

## Schema

### One-time migration (`just new add_games_summary_and_looking_for_players`)

```sql
ALTER TABLE games ADD COLUMN IF NOT EXISTS summary text;
ALTER TABLE games ADD COLUMN IF NOT EXISTS is_looking_for_players boolean NOT NULL DEFAULT false;
```

### New table (`db/custom/create_game_favorites_table.sql`, wrapped with `just make_custom`)

```sql
CREATE TABLE IF NOT EXISTS game_favorites (
    id_game_favorite integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    id_game          bigint NOT NULL REFERENCES games (id_game) ON DELETE CASCADE,
    id_user          uuid   NOT NULL REFERENCES users (id_user) ON DELETE CASCADE,
    UNIQUE (id_game, id_user)
);

-- Register the table, flag it, then let the metatable procedures add the
-- audit columns and the set_updated_at trigger. Same sequence as
-- migrations/20260910172124_do_custom_convert_action_logs_settings_to_id_users.sql.
CALL _p_update_tables();
UPDATE _tables
SET needs_timestamps = TRUE,
    needs_user_ids   = TRUE,
    updated_at       = NOW()
WHERE table_name = 'game_favorites';
CALL _p_update_tables_timestamps();
CALL _p_update_tables_user_ids();
```

`_p_update_tables()` only overwrites `has_*` flags on conflict, never
`needs_*`, so the flags survive later runs. The migration also raises if
`game_favorites` is absent from `_tables` after the first call, as the
action-logs migration does, so a silent miss cannot happen.

### Games seed

`db/seeds/seed_games.sql` gains a `summary` value per row, one to three
sentences taken from each campaign's page on rpg.irun.games, and
`is_looking_for_players = false` everywhere. The seed migration is
regenerated and re-run (nothing is committed yet, so the previous seed
migration file is deleted and replaced rather than stacked).

### Drizzle mirror (`apps/web/src/db/schema.ts`)

Add `systems`, `games`, `gamePlayers`, `gameFavorites` tables and their
relations. Column keys are camelCase, SQL names match the database
(`id_game`, `game_title`, ...). Row types are derived with `$inferSelect`; no
hand-written interfaces for rows.

## Data access

### `apps/web/src/lib/authorize.ts`

```ts
export async function requireUser(): Promise<DbUser>
```

1. `getSession()` (the existing memoised lookup). No session: throw
   `UnauthorizedError`.
2. Select the user row by `session.user.id`. Missing or `is_active = false`:
   throw `UnauthorizedError`.
3. Return the row.

`UnauthorizedError` is a plain `Error` subclass so tests and callers can
distinguish it. Pages still call `requireSession()` for the redirect; actions
call `requireUser()` and never trust ids sent from the client.

### `apps/web/src/app/(app)/(nav)/home/actions.ts` (`"use server"`)

Every export begins with `const user = await requireUser()`.

| Action | Arguments | Returns | Query |
| --- | --- | --- | --- |
| `listMyStories` | `offset` | `StoryCardData[]` | games where `id_created_by_user = user.id` or a `game_players` row exists for `user.id` |
| `listFavoriteStories` | `offset` | `StoryCardData[]` | games joined through `game_favorites` for `user.id` |
| `listLookingForPlayers` | `offset` | `StoryCardData[]` | games where `is_looking_for_players` and `is_active` |
| `createStory` | `unknown` (the form's values object) | `{ ok: false; errors: Record<string, string> }` or redirects | validate with `newStorySchema`, insert with creator and updater set to `user.id`, then `redirect("/home")` |
| `getStory` | `idGame` | `StoryCardData \| null` | one game by id, same projection as the lists; used by the `/home/[id]` stub |
| `listSystems` | none | `{ idSystem, label }[]` | every system ordered by name, version, variant; label is the joined display string |

All list actions: left join `systems`, order by `games.updated_at desc`,
`limit PAGE_SIZE` (10), `offset`. `StoryCardData` is the projected shape:
`idGame, gameTitle, summary, imageUrl, lastPlayed, systemName, systemVersion,
variant`.

Inputs are validated with Zod before use: `offset` must be a non-negative
integer.

## Pages and components

### `/home` (`home/page.tsx`, server component)

- `await requireSession()` first.
- Calls the three list actions with offset 0 in parallel.
- Layout: page container with a header row (`Heading` "Stories" left,
  `Button` "New story" right linking to `/home/new`), then three
  `StorySection`s.

### `StorySection` (`components/stories/story-section.tsx`, client)

Props: `title`, `initialStories`, `loadMore: (offset) => Promise<StoryCardData[]>`.

- Renders a `Heading` and a responsive `SimpleGrid` (1 column base, 2 at
  `md`, 3 at `lg`, 4 at `xl`) of `StoryCard`s.
- Shows an empty-state line when there are no stories.
- Shows a "More" button only while the last fetch returned a full page
  (`length === PAGE_SIZE`). Clicking calls `loadMore(stories.length)`, appends
  the result, and hides the button when fewer than a page comes back. The
  button is disabled while a request is pending.

### `StoryCard` (`components/stories/story-card.tsx`, client)

Props: `story: StoryCardData`.

- `LinkBox` with a fixed aspect ratio (3:4 on phones, 4:3 from `md`), rounded
  corners, overflow hidden.
- Background: `image_url` as a cover image; when null, a neutral surface
  colour. A bottom-to-top dark gradient scrim sits over the image so the text
  stays legible on any cover.
- Top: title (`LinkOverlay` to `/home/[id]`), then system line in small muted
  text: `system_name`, plus ` · variant` when set, plus ` (version)` when set.
  Omitted entirely when there is no system.
- Middle: summary clamped to three lines with `lineClamp={3}`. When the
  summary is longer than `SUMMARY_PREVIEW_CHARS` (200) a "more" link is
  shown; a character threshold rather than a layout measurement keeps the
  rule deterministic and testable under jsdom. Clicking opens a Chakra
  `Popover` anchored to the card containing the full summary. The link uses
  `stopPropagation` and `preventDefault` so it does not follow the card link.
- Bottom right: `last_played` formatted with `Intl.DateTimeFormat` as
  `"Jun 25, 2015"`.

### `/home/new` (`home/new/page.tsx` + `new-story-form.tsx`)

- Server page: `requireSession()`, loads the systems list for the select
  (this read lives in `actions.ts` too, as `listSystems`), renders the form.
- Client form: react-hook-form with `zodResolver(newStorySchema)`. Fields:
  title (required, max 200), system (optional select), summary (optional,
  max 4000), image URL (optional, must be a URL), looking-for-players
  (checkbox). Submits to `createStory`; server-side errors are shown inline.
- `newStorySchema` lives in `src/lib/story-schemas.ts` so the client and the
  action share it.

### `/home/[id]` (`home/[id]/page.tsx`)

Stub: `requireSession()`, shows the title of the game if it exists or a
not-found. Exists only so card clicks land somewhere.

## Error handling

- `requireUser()` throws `UnauthorizedError`; the `(app)` layout's
  `requireSession()` redirect handles the common case before an action runs.
  An action reached with a stale session surfaces as a Next server action
  error, which is acceptable for now.
- `createStory` returns field errors for validation failures rather than
  throwing, so the form can show them.
- Load-more failures leave the section as it was and re-enable the button.

## Tests

Following the existing `node:test` + Testing Library setup:

- `lib/authorize.test.ts`: no session, no user row, inactive user, happy path
  (session and db mocked with `mock.module`).
- `lib/story-schemas.test.ts`: required title, URL validation, max lengths.
- `components/stories/story-card.test.tsx`: renders title, system line,
  formatted date; hides the system line when null; "more" opens the popover
  with the full summary.
- `components/stories/story-section.test.tsx`: More button shown only for a
  full page, appends results, hides when short, empty state.
- `home/actions.test.ts`: integration, skipped unless `DATABASE_URL` is set.
  Seeds are present locally, so it asserts the seeded games appear in
  `listMyStories` for the seed user and that offsets page correctly.

## Dependencies

No new packages. Chakra v3 provides `Popover`, `LinkBox`, `SimpleGrid`; Zod and
react-hook-form are already installed.
